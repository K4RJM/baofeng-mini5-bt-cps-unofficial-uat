# F02 correction and F03 evidence review — October 15, 2026

Baseline: LIVE v20.10, commit `02b5a1dd02a166261590ad679a92723994911d09`. Target correction: v20.11. Publication of the tested correction to LIVE was explicitly authorized; UAT is a separate environment for future development.

## F02 — corrected decoding

The maintainer supplied confirmed hardware observations:

| Field | Radio address | Compact capture offset | Confirmed stored code |
| --- | --- | --- | --- |
| PTT ID delay | `0x900C` | `0x804C` | 28 = 3000 ms |
| VFO PTT-ID | `0x900B` | `0x804B` | 3 = BOTH / start and end |
| VFO A MuteMode | `0x801B` | `0x801B` | 2 = QT/DQT + DTMF |

The decoder previously reduced these codes using `% 7`, `% 3` and `% 2`, respectively. It now preserves the full stored byte. The shared VFO squelch decoder also preserves VFO B byte `0x803B`. B has the same three existing options and its retained factory write frame stores code 2 directly; physical confirmation of B's behavior is still pending. This correction does not infer new signaling semantics.

The existing editor and write validator already support delay codes 0–28, PTT-ID codes 0–3 and squelch codes 0–2 for both VFOs. Their ranges and encoder are unchanged. Unknown codes remain visible as unrecognized saved values, survive DAT export, and are rejected by the existing write validator. They no longer become plausible defaults through modulo reduction. Other unrelated decoder normalization is outside this change.

### Factory CPS versus Bluetooth evidence

The maintainer observed that wired factory CPS displayed defaults for some F02 fields after reading the radio even though independent Bluetooth captures still retained the intended memory values. A later **factory write** changed the delay back to code 0. Those are separate events: a factory display/read conversion can lose a value before a later factory write changes memory. Do not attribute that sequence to this Bluetooth CPS, and do not classify it as a firmware defect without further evidence.

The retained `decoder-varied.img` contains squelch code 2 for both VFOs, while its native read DAT contains 0 for both. The optional fixture checker now permits exactly those two documented differences, keeping the historical native DAT intact. Its general-settings extraction also includes hand-transcribed rules; it is not an independent oracle for every setting.

A complete JSON diagnostic found in an unfinished-named download was preserved privately as a snapshot. Its `latestRead` timestamp is `2026-10-15T04:52:58.145Z`, build 20.10. The 33,344-byte capture contains decoded delay 0, PTT-ID 0, A squelch 0 and A combined byte `0x10`. This corroborates the later memory state and F03 byte, but cannot by itself prove the preceding sequence or the earlier high F02 codes. That earlier evidence is attributed to the maintainer's confirmed observations.

- Fixed transport-byte assertions for the three confirmed high codes, independent of the encoder under test: `0x5F`, `0x34`, `0x35` after the existing CO 7 transform. The table above uses decoded memory codes, not encrypted transport bytes.

F02's demonstrated conversion defect is corrected. These checks establish software preservation, not RF timing or hardware certification. No physical radio operation was performed during this work.

## F03 — remains open; encoder and decoder packing unchanged

The maintainer confirmed that official CPS wrote and read back **VFO A SignalCode 17 and FreqOffsetDir PLUS**, with radio byte `0x800E = 0x10`. The UI's group 17 is stored as zero-based code 16. Current A decoding returns group code 16 and direction 1 for that byte, consistent with that single observed configuration.

This does not identify a unique mapping. Current packing `(direction << 4) | group` maps all three configurations below to the same byte:

| Direction | Displayed group | Group code | Encoded byte |
| --- | --- | --- | --- |
| Off | 17 | 16 | `0x10` |
| Plus | 1 | 0 | `0x10` |
| Plus | 17 | 16 | `0x10` |

Across the full 3-direction × 20-group domain there are **60 inputs but only 52 distinct bytes per VFO**. Bytes `0x10`–`0x13` each have three possible inputs. The unchanged A decoder takes the entire byte as the group; B takes only the low four bits. Both extract direction starting at bit 4. Thus A Minus/group 1 becomes decoded group code 32, and B Plus/group 17 becomes decoded group code 0. The exhaustive round-trip test remains TODO because those mismatches are unresolved.

### Independent and retained evidence

| Evidence | Observed result | Limit |
| --- | --- | --- |

| Retained native full-test writer capture | A Plus/group 20 → `0x13`; B Minus/group 20 → `0x33` | Confirms historical factory output for these inputs, not radio interpretation |
| Retained native read DAT from varied image | A `0x13` → direction 1/group code 19; B `0x33` → direction 3/group code 3 | Shows the asymmetric decoder behavior; factory display is not an authoritative hardware oracle |
| [CHIRP UV17Pro structure inherited by UV5RMini](https://github.com/kk7ds/chirp/blob/832d349e050fbdcde50185f77cdb34fbe5bab57a/chirp/drivers/baofeng_uv17Pro.py#L357-L377) | Declares a 3-bit direction and 5-bit signal code in byte 14 | Implies `(direction << 5) | group`; Plus/group 17 would be `0x30`, conflicting with the observed factory `0x10` |

CHIRP is independent implementation evidence, not sufficient grounds to replace the mapping. The new factory-native DAT for the reported group-17 experiment was not available in the inspected project artifacts; retained historical native DATs and frames were examined instead. No speculative shift/mask change, new combination restriction or firmware diagnosis is included.

### Evidence needed to resolve F03

On a backed-up, identified radio, compare factory DAT plus independent complete captures for a small discriminating matrix: directions Off/Plus/Minus crossed with groups 1, 16, 17 and 20, for A and B. Change one field at a time, reopen/read in factory CPS, and compare both VFO regions and settings for additional state. The known `0x10` collision needs at least Off/group 17 versus Plus/group 1 versus Plus/group 17. Document radio-displayed direction and the selected signaling behavior separately from what CPS displays. Any transmitting check requires the maintainer's separately controlled setup. No physical write is authorized or performed here.
