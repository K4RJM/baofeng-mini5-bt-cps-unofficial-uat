# F07 frequency-preservation correction — v20.12

Date: October 15, 2026. Baseline: v20.11, commit `dcb609729bf2ea29e4ae25785de8666cf824d090`.

## Problem and correction

The channel editor accepts frequencies from 100.00000 to 999.99999 MHz as a file-format representation. The encoder can encode that representation, but the decoder silently returned an empty field at 600 MHz or above. A nonempty receive channel could therefore disappear, or a transmit frequency become blank. Invalid packed decimal (BCD) nibbles were also interpreted as numbers instead of being rejected.

The decoder now preserves valid channel RX/TX frequency text throughout the existing editor format. Only four `FF` bytes are treated as the empty-frequency marker. Invalid decimal digits or nonempty values below the editor's format limit stop decoding with a channel-specific error. The existing failed-read handler retains every raw byte in the diagnostic report and keeps the previous workspace. Empty channels and receive-only TX fields keep their existing representation.

Write-plan validation now rejects nonempty channel frequency values outside the same canonical format, including imported values that unchanged-field edit validation previously skipped. This happens before the write confirmation or Bluetooth connection. It does not alter accepted plans, the encoder, addresses, block lengths, payloads, command order, acknowledgements, no-retry rule, disconnect or reset behavior.

**This is a representation correction, not permission or a claim that the radio operates from 100 to 999 MHz.** In particular, 650 MHz is only a synthetic regression example. It must not be used as a hardware test frequency. Verified receive/transmit capabilities and invalid-frequency behavior on identified hardware remain outstanding. F07 is partially corrected and remains open for that evidence; the total remains seven corrected findings and eight open.

## Verification

- Six of the seven new tests failed on v20.11 before the correction; the empty-channel/receive-only control already passed.
- Seven independently specified BCD vectors are checked in both RX and TX: 100.00000, 146.52000, 433.92500, 599.99999, 600.00000, 650.00000 and 999.99999. Tests compare decoded text, native DAT round trips and complete reconstructed images. The vectors describe byte representation, not operating bands.
- All 96 single-nibble malformed cases are rejected across eight RX/TX bytes, both nibble positions and invalid digits A–F. Nonempty zero/sub-100 MHz encodings are rejected rather than cleared.
- Real application handlers in the isolated test harness retain the original workspace and all 33,344 diagnostic bytes after a malformed capture. Imported out-of-format frequencies are blocked before connection or confirmation. No radio writes occur in those tests.
- Full suite: **77 tests, 73 passing, four expected TODO failures, zero unexpected failures**. The F07 synthetic loss regression now passes. The remaining TODOs reproduce F01, F03, F05 and F10; absence of a TODO is not hardware verification.
- All 21 private-file checks still pass: 16 native DAT round trips and three complete DAT/capture pairs with every field and all 33,344 bytes matching. F01/F03/F08 evidence remains unchanged.
- The older native comparisons still match 1,042 frames / 66,688 bytes and two retained decoder fixtures, with the previously documented F02 oracle differences.
- Nine protected files, the encoder, Bluetooth reader and connection-recovery helper remain unchanged. The decoder changes only channel frequency handling; `writer.mjs` changes only preflight validation in `makePlan`. No transport method changes.

## Physical read-first checklist

1. Confirm the site shows build **20.12**. Keep the existing original factory DAT and raw diagnostic files.
2. Use the radio's current known configuration. Enable Wireless CPS, stop scanning, connect and choose **Read radio**. Do not add synthetic boundary frequencies for this check.
3. Check the populated channel count, several known RX/TX frequencies, names and any receive-only channels. Check the PTT-ID delay, VFO PTT-ID and VFO A squelch values against the most recent known configuration; do not assume a prior factory write left them unchanged.
4. Save a new DAT copy and diagnostic report. Compare the DAT settings with the known configuration, or provide both files for offline comparison.
5. If a read reports an undecodable frequency, retain the diagnostic and stop that test. The error does not establish a defective radio or firmware. The prior workspace is retained and is not a successful new read.

This checklist performs no memory write. A later write/reboot/read-back test needs an agreed valid configuration and explicit approval; F01, F03, F05, F06 and F08 limitations still apply. No physical radio was connected, read or written during development of this correction.
