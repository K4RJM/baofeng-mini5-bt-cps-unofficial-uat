## Existing completion handling and regression coverage

Writer.upload counts each valid ACK, marks all 262 blocks acknowledged as written-unverified, and never retries an uncertain write. releaseAfterAcknowledgedWrite permits browser-side cleanup only after all ACKs and an idle writer; it sends no radio bytes or reboot opcode. The app recognizes disconnect after all ACKs as expected reboot, waits for explicit restart confirmation and reconnect, then verifies stored data. It does not confuse acknowledgements with readback verification.

Existing cleanup tests cover completed, already-disconnected, failed-host-cleanup and uncertain-last-block paths. New regressions use the literal captured channel 71 record and the real application handlers with a simulated persistent radio: write, acknowledged disconnect, explicit reconnect, verification, and no second write.
