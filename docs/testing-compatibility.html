HAM-RX BAOFENG MINI-5 · UAT 20.27

Testing & Compatibility

This document separates physical-radio evidence from software checks. UAT 20.27 changes the interface and documentation only. It does not change Bluetooth, encoding, decoding or programming behavior.

Current UAT verification

The v20.27 candidate is undergoing automated and browser verification. Final results will be recorded here after deployment checks. No physical-radio write has been performed for this interface release.

Physical-radio evidence and audit history

K4RJM has physically tested Bluetooth programming, reads and reconnection, including successful build 18 programming and normal operation on Radio 100 / firmware V0.05 / hardware V1.7. Factory CPS files and independent Bluetooth memory captures support the build 20.11 settings-decoder correction. Typical programming took less than one minute in the reported tests.

Build 20.12 corrects channel-frequency decoding. Build 20.14 checks channel edits and programming against the recorded factory CPS ranges and 1.25 kHz grid. Imported and read values remain preserved, with unsupported channel frequencies blocked from programming. F07 is closed based on completed factory CPS testing and regression coverage; VFO reception is separate from memory-channel limits. F03 is an accepted factory-compatible VFO limitation: OFF/group 17, PLUS/group 1 and PLUS/group 17 can read back as PLUS/group 17. Memory-channel programming is unaffected. F06 is closed: the original build 20.14 before/after captures confirm the intended channel 71 addition and channel 999 clearing after reboot, with no changes outside those areas. F05 now requires a complete, fresh 5RMINI identification for the current connection before programming. F01 is closed as accepted factory-compatible memory reconstruction, supported by retained factory CPS output and radio captures. Build 20.20 corrects F08 by reproducing the factory channel-999 trailing-memory pattern. K4RJM’s completed factory programming and Bluetooth captures establish channel-999 capability; the correction matches all 33,344 captured bytes. Ordinary channel edits preserve channel 999. No additional physical Bluetooth write was performed during development of this build. Build 20.21 adds deadlines for stalled Bluetooth calls and stops cancelled sessions from continuing. A timed-out write remains uncertain and is never retried automatically. If a browser call remains pending, save your work and wait or reload before reconnecting. Automated fault tests verify this correction; it does not establish a fix for the intermittent PC/radio Bluetooth-toggle symptom. Build 20.22 completes F13 with independent captured-byte tests, asynchronous Bluetooth simulations and real-browser checks. All 15 original audit findings have final dispositions, including the accepted F01 and F03 factory-compatible behavior. Automated and simulated tests supplement this physical evidence. See the Audit status and evidence for completed evidence and specific remaining work. A matching model is not firmware identification.

Automated testing

Regression checks cover native DAT preservation, captured memory, validation, programming safeguards, asynchronous transport failures and simulated browser workflows. Simulations do not communicate with a physical radio and cannot establish compatibility with untested firmware.

Unresolved limitations

The shared VFO representation remains an accepted factory-compatible limitation. Native DAT backups do not include firmware or every memory byte. The intermittent need to toggle Bluetooth on the PC and radio is not established as fixed. The stock CPS default-display observation is separate and must not be classified automatically as a firmware defect.

Physical evidence applies to the tested radios and configurations. A matching model identity does not identify firmware. Confirm changed settings by readback and normal radio operation.
